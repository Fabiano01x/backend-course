### 1. The Foundation: OpenAPI and Automatic Generation

Before we look at the documentation itself, it's important to understand *how* FastAPI creates it. The framework adheres to the **OpenAPI Specification**, a widely adopted standard for describing RESTful APIs in a machine-readable format.

FastAPI inspects your code—your path operation decorators (`@app.get`), your Pydantic models, your type hints, and even your function docstrings—to generate a detailed OpenAPI schema. This schema is a JSON file (by default available at `/openapi.json`) that describes every aspect of your API. This JSON schema is then used to power two beautiful, interactive documentation frontends that come bundled with FastAPI.

#### Step 1: Add API-Level Metadata

First, let's provide high-level information about our API. In your `main.py`, pass these arguments to the `FastAPI` constructor. We can pull some of this information from our `settings` object that we created in the last lesson.

```python
# in main.py
from fastapi import FastAPI
# ... other imports
from .dependencies import get_settings

startup_settings = get_settings()

# Define API metadata
api_description = """
Our Full-Stack Application API helps you do awesome things. 🚀

## Items

You can **read items**.

## Users

You will be able to:
* **Create users** (_not implemented_).
* **Read users** (_not implemented_).
"""

app = FastAPI(
    title=startup_settings.APP_NAME,
    description=api_description,
    version="0.1.0",
    contact={
        "name": "API Support",
        "url": "http://www.example.com/support",
        "email": "support@example.com",
    },
    license_info={
        "name": "MIT License",
        "url": "https://opensource.org/licenses/MIT",
    },
    # The `debug` argument is already set from our settings
    debug=startup_settings.DEBUG_MODE,
)

# ... rest of your main.py file
```
Notice that the `description` field accepts Markdown, allowing you to create rich, formatted text.

#### Step 2: Group Endpoints with Tags

As your API grows, having a long, flat list of endpoints becomes unmanageable. You should group related endpoints using `tags`. The best place to do this is on the `APIRouter`.

Let's imagine you have a router for handling users in `app/routers/users.py`:

```python
# in app/routers/users.py
from fastapi import APIRouter

router = APIRouter(
    prefix="/users",
    tags=["Users"] # This tag will group all endpoints in this router
)

@router.get("/")
async def get_all_users():
    return [{"username": "rick"}, {"username": "morty"}]
```

#### Step 3: Add Detail to Individual Endpoints

Finally, let's add more descriptive text to a specific endpoint. You can add a `summary`, a more detailed `description`, and information about the responses.

```python
# Continuing in app/routers/users.py

@router.get(
    "/",
    summary="Retrieve all users",
    description="Provides a list of all registered users in the system. This endpoint is for demonstration purposes.",
    response_description="A JSON array of user objects"
)
async def get_all_users():
    """
    Note: FastAPI will use the function's docstring as a description
    if the `description` parameter is not provided in the decorator.
    It's generally better to use the parameter for consistency.
    """
    return [{"username": "rick"}, {"username": "morty"}]

@router.get(
    "/legacy",
    summary="A deprecated endpoint",
    deprecated=True # This marks the endpoint as deprecated in the docs
)
async def get_legacy_data():
    return {"message": "This is a legacy endpoint and will be removed soon."}

```

After making these changes, restart your `uvicorn` server and refresh the `/docs` and `/redoc` pages. You will see a much richer, more organized, and professional-looking documentation interface.

### Conclusion

Congratulations on completing the "Modern Python Backend with FastAPI" module! You've built a solid foundation, from creating a structured application and handling configurations securely to now providing professional-grade documentation.

**Key Takeaways:**

*   FastAPI automatically generates an **OpenAPI schema** from your code (Pydantic models, type hints, decorators).
*   This schema powers two built-in documentation interfaces:
    *   **Swagger UI (`/docs`)**: An interactive playground for developers to test API endpoints.
    *   **ReDoc (`/redoc`)**: A clean, read-only interface for creating polished, human-readable documentation.
*   You can and should **enhance your documentation** by adding metadata to the `FastAPI` instance, using `tags` to group endpoints, and providing detailed `summary`, `description`, and `response_description` information for each endpoint. This is a standard practice in professional development environments.
